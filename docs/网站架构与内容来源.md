# 网站架构与内容来源梳理

> 生成时间：2026-11-10　适用版本：`ai-daily-news@0.1.0`（Astro 5 静态站）

## 一、整体架构

```
① 采集层            ② 处理层                     ③ 展示层           ④ 部署层
┌──────────┐    ┌──────────────────────┐    ┌───────────┐    ┌────────────┐
│ RSS 资讯  │───▶│ 清洗 → 过滤 → 精筛   │───▶│           │    │            │
│ 政策通知  │    │ → 去重 → 打分 → 翻译 │    │ news.json │    │ GitHub     │
│ 排行榜   │    │                      │    │ policy    │───▶│  Actions   │
└──────────┘    └──────────────────────┘    │ leaderboard│    │     +      │
      │                    │                └───────────┘    │ 阿里云 ECS │
      │                    ▼                      │          └────────────┘
      │              src/data/*.json               ▼
      └────────── 定时触发（GitHub 06:16 / ECS 08:00）
```

三个数据文件驱动四个页面，站点本身是纯静态产物，没有运行时后端。

## 三、资讯处理管线（关键环节）

`fetch-news.mjs` 一条资讯从抓到写盘要过 11 道关：

| # | 环节 | 逻辑 | 可调参数 |
|---|---|---|---|
| 1 | 拉取 | 18 个 RSS 并行解析，单源失败不影响其他 | `SOURCES` |
| 2 | 基础过滤 | 必须有标题/链接/合法时间，且 7 天内 | `DAYS=7` |
| 3 | 垃圾词过滤 | 培训/报名/限时优惠等复合词 | `SPAM_KEYWORDS` |
| 4 | 赞助过滤 | sponsored / presented by / 推广位 | `SPONSORED_KEYWORDS` |
| 5 | URL 去重 | 同链接只留一条 | — |
| 6 | 占位摘要修复 | 摘要 <15 字或只有"点击查看全文"时，抓原文 og:description 重建，限 15 条 / 5 并发 | `fixPlaceholderSummaries` |
| 7 | AI 相关性 | 可信媒体必须命中 AI 关键词，核心源豁免 | `isAIRelated` |
| 8 | **LLM 精筛** | qwen-plus 批量 10 条/批，输出相关性/软文/分类/摘要/信息增量分 | `BATCH=10` |
| 9 | 单源上限 | 每源最多 15 条，防止 arXiv 挤占 | `MAX_PER_SOURCE=15` |
| 10 | 跨源去重 | 标题+摘要指纹 Jaccard ≥ 0.35 视为同一事件，保留 core 优先、最早的一条，额外源数记为 `coverage` | `DEDUP_THRESHOLD=0.35` |
| 11 | 截断 + 打分 | 先保公司相关条目，再补足至 100 条；热度 = 多源 IDF 分 + coverage×5，再乘 48 小时半衰期衰减 | `MAX_ITEMS=100` |

最后英文条目走 `translate.mjs` 翻成中文（结果缓存到 `translation-cache.json`，只翻新增）。

### 3.1 LLM 精筛产出的字段

每条可信媒体条目可能带上：

```json
{
  "is_ai_related": true,     // 是否与 AI 直接相关，false 直接丢弃
  "is_promo": false,          // 是否软文，true 直接丢弃
  "category": "大模型",        // 7 选 1，覆盖关键词分类结果
  "summary": "……",           // 20-50 字重写摘要
  "score": 4                  // 1-5 信息增量分
}
```

落到 `news.json` 后只有 `tags`、`summary`、`llmScore` 三个字段生效。**`llmScore` 目前只记录，没有参与任何过滤或排序**，这是内容质量可优化的最大空档。

## 四、页面结构

| 页面 | 文件 | 内容 |
|---|---|---|
| 首页 | `src/pages/index.astro` | 搜索栏 + 筛选栏 + 按日期分组的资讯流 + AI 日报 + AI 公司动态 |
| 排行榜 | `src/pages/leaderboard.astro` | 卡片式榜单，前三名 podium，维度切换由客户端重排 |
| 关于 | `src/pages/about.astro` | 政策背景说明 |
| 反馈 | `src/pages/feedback.astro` | Formspree 提交 |

首页筛选维度：

- **全部**：按日期倒序分组，每组先展示 10 条，其余折叠
- **AI 日报**：当天热度最高的 5 条
- **AI 公司动态**：按 20 家知名公司分组，组内时间倒序
- **内容标签**：大模型 / 智能体 / 芯片算力 / 具身智能 / 政策与安全 / 商业融资 / AI 动态
- **最新资讯**：政策通知单独成组

## 六、当前内容质量问题

| 问题 | 表现 | 根因 |
|---|---|---|
| 摘要对位风险 | 模型少返、多返或乱序时整批摘要会串到别的标题上 | `llm-classify.mjs` 按数组下标回填，没有 id 校验（**已修：改为按 index 精确回填 + 单条补抓**） |
| 合集摘要只提一条 | 「早报」「早知道」类标题并列多条新闻，摘要只挑其中一条写，读起来像别的新闻 | 提示词让模型「概括核心内容」，模型理解为挑最重要的那条（**已修：识别合集并加〔合集〕标记，要求概括 2-3 条**） |
| arXiv 密度过高 | 单日 20+ 条学术论文标题占据列表 | core 源全量采集，无数量约束 |
| `llmScore` 未使用 | 低价值条目与重要新闻同样展示 | 分数只落盘，没进筛选和排序 |
| 热度排序 vs 时间分组 | 同一天内卡片不是时间顺序 | `news.json` 按 heat 降序，页面按日期分桶后保持原序 |
| 无人工复核 | 全自动上线，错漏只能靠事后发现 | 缺审核环节 |
